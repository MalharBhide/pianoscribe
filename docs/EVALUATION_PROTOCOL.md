# Evaluation Protocol (Milestone A)

## 1. What we measure

Full path audio → exported/played score, at stages:
`raw detections → filtering → arrangement → quantization → export`.
Metrics computed from canonical `Score` (performance timing) and from the
exported MIDI (must match within rounding).

## 2. Note matching

One-to-one pitch/onset matching, greedy by onset error, tolerance **±50 ms**
(default, declared per run; 30 ms and 100 ms reported as diagnostics).
A match requires equal MIDI pitch + |onset error| ≤ tolerance.
Unmatched estimates = extra; unmatched references = missing.

Reported separately (never folded into one number):
- precision, recall, F1 (note level)
- pitch errors (wrong pitch within tolerance window, counted as extra+missing pair)
- onset timing error: mean/median/p95 of |err| over matches
- release/duration error: mean/median/p95 of |end err| over matches;
  duration F1 with ±20% or ±100 ms criterion
- extra / missing counts
- repeated-note preservation: reference same-pitch pairs with gap < 500 ms;
  fraction where estimate has ≥2 attacks of that pitch overlapping the span
- complete-chord recovery: reference simultaneities (≥3 notes, onsets within
  50 ms); fraction fully recovered (all pitches matched)
- extra in-chord tones: mean extras per recovered/partial chord
- melody preservation (arrangement + piano): F1 on melody-role reference notes
- accompaniment clutter: extras per second outside melody match windows
- runtime + peak RSS per recording

## 3. Corpora

- `fixtures/synth_*`: synthesized WAV + exact MIDI ground truth generated by
  `scripts/make_fixtures.py` (melody, chords, repeats, sustains, 1-min
  excerpt). Deterministic; committed.
- Duration ladder: synthetic 5 s, 30 s, 1 min, 5 min clips test windowing and
  drift; 15/30-min runs are timed chunk-loop tests (no full audio committed).
- Release test set: `fixtures/release/` is write-once; never tune against it.
  This slice ships with synth fixtures only; real-recorded piano + mixed-song
  corpora are listed as required before any production claim.

## 4. Arrangement judgment

Objective melody/harmony checks (above) + fixed human rubric (1–5 each):
melody recognizability, harmonic plausibility, playability, clutter, rhythm
readability. Multiple voicings valid; rubric, not reference-match, decides.

## 5. Release gates

`docs/release_gate.yaml` holds numeric thresholds per mode. `scripts/eval.py`
writes `reports/eval_<tag>.json`; `scripts/check_gate.py` compares and fails
loudly. A failing candidate is not deployed; the report names the responsible
stage. Thresholds are requirements under test, not accuracy claims.

## 6. Anti-leakage

Splits by work + recording identity; excerpts/codecs/augmentations of the same
work never cross partitions. User uploads never used for training/eval without
explicit permission. Local training storage budget < 25 GB.
